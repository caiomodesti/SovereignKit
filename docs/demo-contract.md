# Controlled Experiment and Demo Contract v0.1

## Purpose

Demonstrate, using only stored measurements, that matched probes produce distinct and reproducible `HEALTHY`, `DEGRADED`, `ASYMMETRIC`, and `INSUFFICIENT_DATA` classifications.

## Controlled topology

```text
Observer
  |-- Route A proxy --------|
  |-- Route B proxy --------+--> project-owned local validator + test program
  `-- Route C proxy --------|

ObservationQuorum
  |-- Reader 1 RPC ---------|
  |-- Reader 2 RPC ---------+--> same local validator in the first experiment
  `-- Reader 3 RPC ---------|
```

All proxies and upstreams are project controlled. Route labels do not imply physical independence.

## Preconditions

- Component versions and source commit are recorded.
- Validator ledger is reset and test program is deployed deterministically.
- Observer and three reader endpoints are healthy.
- Observer public key is allowlisted.
- Routes use the same configuration profile except their logical endpoints.
- `MATCHED_CONTROL` and `PROGRAM_X` pass the matching validator.
- Randomization seed and probe ranges are fixed before execution.
- Analysis process cannot access proxy mode configuration.

## Canonical phases

### Phase A: healthy baseline

- All proxies: `PASS_THROUGH`.
- 30 complete units per route/class.
- Expected classification: `HEALTHY` for A, B, and C.

### Phase B: general degradation

- Route A deterministically rejects both classes for 70% or more of probes using a precommitted probe-index schedule.
- Routes B and C: `PASS_THROUGH`.
- 30 complete units per route/class.
- Expected classification: Route A `DEGRADED`; B and C `HEALTHY`.

Deterministic scheduling is required so the scenario is reproducible. The detector receives only measurement results, not the schedule.

### Phase C: selective rejection

- Route A: `REJECT_CLASS(PROGRAM_X)`.
- Routes B and C: `PASS_THROUGH`.
- 30 complete units per route/class.
- Expected classification: Route A `ASYMMETRIC`; B and C `HEALTHY`.

### Phase D: insufficient data

- All proxies: `PASS_THROUGH`.
- 10 complete units per route/class.
- Expected classification: `INSUFFICIENT_DATA` for all routes.

## Unique matched transaction requirement

The tuple `(experiment, phase, observer, route, class, probe_index)` maps to exactly one transaction signature. No signature may appear under two routes or classes. Pairing validation runs before submission, and failures are retained as exclusions.

## Expected lifecycle evidence

- Proxy rejection should normally yield `RPC_REJECTED`, followed by observation until `EXPIRED` or a contradictory ledger observation.
- Pass-through success should yield `RPC_ACKNOWLEDGED`, then quorum `OBSERVED_EXECUTION_SUCCESS`, then `CONFIRMED`; `FINALIZED` is tracked separately.
- Acknowledgment alone never contributes to success rate.

## Reproduction commands contract

These commands are targets for later sprints; Sprint 0 does not implement them:

```text
pnpm demo:reset
pnpm demo:start
pnpm demo:deploy-test-program
pnpm demo:run --phase healthy
pnpm demo:run --phase degraded
pnpm demo:run --phase asymmetric
pnpm demo:run --phase insufficient-data
pnpm demo:classify
pnpm demo:summary
pnpm demo:verify
```

`demo:verify` must rebuild summaries from raw files, compare content hashes, verify expected classifications, and fail if the analysis consumed proxy configuration.

## Presentation contract

The eventual 60–90 second presentation may replay pre-collected deterministic measurements or run a reduced clearly labeled live window. It must not claim that 30–60 samples constitute production calibration, and it must not use frontend flags to generate classifications.

## Failure conditions

The experiment fails if any of the following occurs:

- identical signed transaction reused across comparative routes;
- mismatched transaction structure included in analysis;
- classification requires proxy-mode input;
- success is counted from RPC acknowledgment;
- fewer than 2/3 readers support an observation decision;
- general degradation becomes `ASYMMETRIC`;
- summary cannot be regenerated byte-for-byte after canonical normalization;
- controlled findings are described as third-party censorship.
